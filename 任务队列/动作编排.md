## 〇、物理前提（已核对官网与 SDK，详见 `G1能力核对.md`）

本文所有动作都只在这五条前提内成立，超出的一律不写：



1. **头 2 DOF**（`head_joint1/2`），官方用途就是 "注视 / 相机朝向控制"；**臂 7×2**，`left_arm_joint1..7`。

2. **头部只有左右两个彩色相机，没有深度**。深度只有两处：手臂深度相机、`FOUNDATION_STEREO` 立体感知（`LIGHT_STEREO` 此版本不支持）。

3. **身高 173 cm，升降 0.96–1.54 m**（`set_leg_height`）。站立约 1.54 m，降身一次要 **3–4 s**（给 1.5 s 服务端会自行延长）。

4. **末端可换**：夹爪（宽 0–0.12 m，1 关节）/ 吸盘 / 灵巧手；**出厂默认左夹爪 + 右吸盘**，必须先看机确认。

5. **手臂没有姿态库**："零位" 是 home 配置，不等于自然下垂。下垂角、指物角、摆手角**必须真机标定**后写进代码。

底盘相关：导航速度分量下限 **0.05 m/s**（不是想设多慢都行）；原地转向用 `set_base_pose(0,0,Δyaw,frame_id="rel(0)")` 闭环，不用 `navigate_with_velocity` 估时长。

## 二、说话的体态：4 类，同类同姿态（不搞多样化）

你提的核心是对的：**说的时候不能站着不动，但也不需要花样多**。只保留 4 类，每类固定一套，永不变体、永不随机。



| 体态         | 用在哪类话                     | 头                           | 臂                               | 时序                        |
| ---------- | ------------------------- | --------------------------- | ------------------------------- | ------------------------- |
| **D-1 回答** | 回答老人的问题、闲聊、远程告知           | 正向平视老人（yaw 对齐），句首 pitch −2° | **M-14 下垂**（不做手势）               | 头先 0.2s 到位，与语音同起          |
| **D-2 提问** | 机器人向老人提问                  | 先转向目标（pitch −3\~−5°，略低头看物）  | 指物时 M-15，否则 M-14                | 说完**保持 1s 不动**（这是 "我在等您"） |
| **D-3 肯定** | 老人答得好                     | **M-03 点头 1 次**             | 一侧小臂前抬 8–12cm 再放下（0.8s）         | 与 "对啦" 同起，说完收回            |
| **D-4 安慰** | 老人答得不好 / 跌倒询问 / 老人说 "我不行" | **M-04 侧头 1 次**             | 一侧小臂**掌心向上**小幅前伸～10cm 后收回（1.2s） | 与 "没事" 同起，说完收回            |

**四条使用规则**



1. **一句话只用一个体态**，句子中间不换。中途换体态，老人会以为机器人在变卦。

2. **同类话永远同一体态**。今天 "答对" 是点头 + 抬手，明天还是这一套，不要做变体。

3. **头先动，手后动**。人说话时视线先到，手跟着来；反了就像在打手势聊天，很假。

4. **说完 0.3s 内回位**（臂回 M-14，头回正向）。不收回去，下句话就从半举着手开始。

**为什么只有 4 类就够**：老人判断 "机器人有没有在听" 靠的是三件事 —— 头有没有对着我、说话有没有停顿等我、我做对做错时反应变不变。这 4 类正好覆盖这三件事，第 5 类开始就是给评委看的，不是给老人看的。

### 指物手势的依据（夹爪版，不是灵巧手版）

人类标准指物是四要素：**食指伸出、其余手指屈曲进掌心、掌心旋前朝下（或朝身体中线）、手臂伸展**\["[https://www.frontiersin.org/articles/10.3389/fpsyg.2017.01319/full](https://www.frontiersin.org/articles/10.3389/fpsyg.2017.01319/full)"]；目标远或要让对方一眼看懂时改用**整手指**（whole-hand pointing）\["[https://pmc.ncbi.nlm.nih.gov/articles/PMC2080771/](https://pmc.ncbi.nlm.nih.gov/articles/PMC2080771/)"]。时序上**视线 / 头部先到目标，手后到，且指的过程中视线一直锚在目标上**\["[https://journals.physiology.org/doi/full/10.1152/jn.2001.86.2.961](https://journals.physiology.org/doi/full/10.1152/jn.2001.86.2.961)"]。

**但我们的末端是夹爪，没有食指。** 所以不能照抄第一条，改成 HRI 里已验证的替代逻辑：



| 人类要素           | 夹爪怎么替                                          | 依据                            |
| -------------- | ---------------------------------------------- | ----------------------------- |
| 食指伸出（造一根 "指针"） | **夹爪闭合成薄片，绕指向轴竖立**—— 薄片的 "锋面" 沿指向方向，看起来像一根扁的指针 | 末端朝目标是最能让人读懂意图的特征             |
| 掌心旋前朝下 / 朝身体中线 | 薄片**竖立**（不横躺）。横躺像 "递东西给您"，竖立才像 "指"             | —                             |
| 手臂伸展           | 肩前屈约 60°、肘近伸直；**前臂轴线延长线穿过目标**                  | 机器人指物的量化定义就是 "肘→腕向量与腕→目标向量同向" |
| 视线先到并锚定目标      | 先 M-02 转头到目标（0.4–0.5s）再出手，指的过程中头不回看老人          | 头 + 臂同时指，比只用一样更容易被看懂          |

\["[http://www.robotics.usc.edu/\~rossmead/docs/2011/2011StClairEtAl\_HRI2011.pdf](http://www.robotics.usc.edu/~rossmead/docs/2011/2011StClairEtAl_HRI2011.pdf)","[http://www.sciencedirect.com/science/article/pii/S0167947317300899](http://www.sciencedirect.com/science/article/pii/S0167947317300899)","[https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2023.1110534/full](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2023.1110534/full)"]

**夹爪的三条硬规矩**



1. **指的时候夹爪必须闭着。** 张开的夹爪＝"我要抓这个东西"，老人会伸手来拦，或以为机器人要抢东西。

2. **薄片竖立，不横躺。** 横躺的末端会被读成 "递 / 请"。

3. **不做 "单指"。** 单指需要手指，夹爪做不出来；也不要为了像人而抬到脸前做假动作 —— 整臂前伸 + 闭合末端最稳、最不容易撞。

**其余不变量**：先转头再出手；指的过程头锚定目标；判等结束才收臂；目标在侧后方 >90° 时不用臂，改 M-05 半身转 + 头指。

## 五、连贯性：链与链之间



1. **同一时刻只动一个组**。头与底盘、头与臂都不许并发，串行且间隔 ≥0.3s。

2. **每条链收尾必 M-10**。

3. **手臂只有两种状态**：下垂（M-14）／指物（M-15）。**不许 "半举着" 进下一条链**—— 进链第一件事就是 M-14 归位。

4. **交接留 1 秒**：先回正，再开口。

5. **老人说话时底盘不动**。

6. **抢占固定序列**：M-01 → M-05（若不在正面）→ 播报。

7. **相机只订阅一次**：`subscribe_video_data` 一次订阅、回调分发给各链。**不许各链各调&#x20;**`get_rgb_data(once=True)`**&#x20;轮询**，同一副相机会互相抢帧。

8. **控制器不许抢**：`LEG_HEIGHT_CTRL`（降身）与底盘导航控制器互斥；降身期间不做导航，导航期间不降身（跌倒链是先到位再降身，天然满足）。

9. **只允许一处并行**：跌倒链的 "腿降身 + 臂摆手"（不同链、都慢）；其余任何两组同时动都算抽风。

**三个禁止动作**：边走边大幅转头；连续点头 ≥2 次；摇头表否定（改 M-04）。

## 八、情绪动作链与编排器（M-12 已落地，2026-11-07 并入）

### 8.1 屏幕表情接口（M-12 的实现，随部署包交付）

- **载体**：`player.py`（xcu 上常驻），离线渲染的帧序列（8 情绪 × 循环帧/过渡帧/眨眼帧）
- **帧目录**：`frames_1080x1920`（G1 胸屏 1920×1080 竖装，**优先验证**）／`frames_1920x1080`（横装）；渲染器 `render_frames.py` 可按实际分辨率重出
- **接口**：`POST http://127.0.0.1:8901/emotion`，body `{"emotion":"happy"}`；同情绪重复请求自动忽略
- **防闪设计**：切换默认直切（不播过渡帧）+ 0.25s 去抖（连续请求只执行最后一个）；`--fps` 默认 8，日志带延迟监控
- **自带生命感**：idle 循环帧（呼吸微动/弹跳/脉动）+ 随机眨眼（sleepy 时不眨）——不需要编排器参与

**规则（并入 §五）**：

1. **表情先行，身体跟上**：M-12 先切（<0.3s 生效），头 0.2s 后动——人也是先变脸再动身子。
2. 情绪链全部复用现有模块的限速参数，**不新增任何速度/角度量级**；点头上限 1 次、不用摇头，均不变。
3. **情绪链不碰底盘**（本就不该在说话时挪窝，天然满足 §五第 5 条）。
4. **与对话链互斥**：老人说话/四条主链运行期间，情绪层只切屏幕、不动头；跌倒/远程链运行时情绪链整体忽略（M-01 优先级最高）。
5. 链尾必 M-10 回正（含头回 0 位）。

**M-16 比心（新，默认关闭）**：双臂前伸、末端合拢——姿态思路直接抄官方 SDK 入门教程 Example1（比心动作）。前提：右臂是夹爪而非吸盘（§七缺口 1 同源），真机标定后填角。仅路演演示用，日常链不开。
