## 一、硬件真值（官网 + SDK 一致的部分）



| 项        | 真值                                                                                                                                                   | 依据                                   | 对编排的意义                           |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | -------------------------------- |
| 身高 / 臂展  | 173 cm / 190 cm                                                                                                                                      | 官网 G1 产品页                            | 站在坐着的老人面前是 "俯视"，**必须降身或低头**      |
| 身体升降行程   | 65 cm；腕部工作高度 0–210 cm                                                                                                                                | 官网参数 + `set_leg_height`              | 降身是真实可用的，不是噱头                    |

## 二、相机与深度（**最颠覆的一条**）



| 事实                                                                                    | 依据                                                                          | 后果                                   |
| ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------ |
| 头部只有 **左、右两个彩色相机**（`HEAD_LEFT_CAMERA` / `HEAD_RIGHT_CAMERA`，frame 名带 `color_optical`） | `SensorType` 枚举 + 传感器 frame 对照表                                             | 转头＝**视野跟着转**，所以 "头部指向" 有效            |
| **头部没有深度相机**                                                                          | `get_depth_data` 原文：仅 `LEFT_ARM_DEPTH_CAMERA` / `RIGHT_ARM_DEPTH_CAMERA` 可用 | "转头指物顺便测距"" 看老人是否贴地 "**都不能靠头部直接拿深度** |
| 深度来源只有两处：**手臂深度相机**、`FOUNDATION_STEREO`**&#x20;立体深度**（`LIGHT_STEREO` 此版本不支持）          | `get_depth_data`、`PerceptionModule` 枚举                                      | 跌倒 "深度贴地" 判据必须改成本表的方案（见下）            |
| 另有 4 个环视彩色相机、底盘激光雷达、超声波阵列                                                             | `SensorType` 枚举                                                             | 跟随 / 避障可以辅助，但环视相机朝向固定、不跟头            |

**由此必须改的三条**：



1. **认知指物不做 "深度测方位"**：目标方位用头部彩色像素 + `get_transform` 换算到 `base_link`，需要深度时调立体感知，或干脆只做 2D 判断（老人在画面里能看到目标就够）。

2. **跌倒 "贴地判定" 不能写成 "深度差 <0.35 m" 这种依赖头深度的判据**：改为 "2D 姿态判据（bbox 长宽比、肩髋夹角、头低于髋、YOLO-pose conf）+ 立体深度做二次确认"，立体不可用时只信 2D。

3. **共享取流**必为 `subscribe_video_data` **一次订阅 + 回调分发**；不要多个模块各调 `get_rgb_data(once=True)` 轮询，同一相机会互相抢帧。

## 三、动作接口真值（每个模块该用哪个 API）



| 动作               | 该用的 API                                                                                                           | 原文依据                                                     | 不许用什么                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 转头（M-02）         | `set_joint_positions(["head"], [yaw,pitch], speed_rad_s=0.3)` 或 `execute_joint_trajectory(joint_groups=["head"])` | `G1JointGroup.HEAD` = 2 DOF；示例 `{"head", {0.0000, 0.0}}` | 不许一帧跳变（文档警告 "角度突变会导致运动过快"）                                                           |
| 原地转向（M-05）       | `set_base_pose(0, 0, Δyaw, frame_id="rel(0)")` —— 相对当前位姿的闭环位姿控制                                                   | `set_base_pose` 原文：`rel(0)` = 相对当前底盘位姿解释                 | **不要用&#x20;**`navigate_with_velocity`**&#x20;靠 duration 估角度**（它是开环定时，转不准）            |
| 靠近 / 后退（M-06/07） | `navigate_to_goal(goal_pose, omni_plan=True, timeout=...)`；前置 `is_localized()` 必须为真                               | `navigate_to_goal` 原文 Note                               | 不许不查定位就直接导航                                                                          |
| 降身（M-11）         | `set_leg_height(z, duration=3~4)`，z ∈ \[0.96, 1.54]                                                               | `set_leg_height` 原文                                      | **duration 给太短会被服务端强行延长**，别写 1.5 s；**切到 LEG\_HEIGHT\_CTRL 期间不许同时导航**（控制器互斥）          |
| 双臂归位（M-14）       | `set_joint_positions(["left_arm","right_arm"], 预设 14 个角, speed_rad_s=0.3, timeout_s=3)`                           | `set_joint_positions` 支持 "腿部、头部、左臂、右臂" 组                 | **不许用&#x20;**`move_whole_body_joint_zero`**&#x20;当收尾**：它是规划器动作，默认 15 s 超时，进不了 1 秒级节奏 |
| 夹爪闭合（M-15）       | `set_gripper_command("left_gripper", width_m=0.005, velocity_mps=0.03, effort=5)`                                 | `set_gripper_command` 原文（宽度 0–0.12 m）                    | 不许张着夹爪去指                                                                             |
| 摆手（M-13）         | `set_joint_positions` 到两个预设角交替（**肩 / 肘小幅左右摆**）                                                                    | 7-DOF 臂有腕关节，但**文档不说明哪个是腕的哪个轴**                           | 不许依赖 "腕部单独摆" 这种没依据的实现                                                                |
| 急停（M-01）         | `stop_navigation()` + `stop_base()`；真急停用 `emergency_stop()`                                                       | `stop_base`、`emergency_stop` 原文                          | 别把 `emergency_stop()` 当日常动作：它是安全机制，恢复要走 `resume_from_emergency_stop`                 |
| 语音输出             | `write_audio_stream_output(pcm_str, stream_id)`，PCM 16k/16bit/mono，先 `set_volume(100)`                            | 官方示例 `play_audio-stop_audio`                             | 不许直塞 mp3/44.1k                                                                       |

## 四、文档**没有给**、必须真机量的三件事



| # | 缺什么                     | 为什么文档给不了                                  | 怎么量                                                                               |
| - | ----------------------- | ----------------------------------------- | --------------------------------------------------------------------------------- |
| 1 | **手臂 "自然下垂" 的 14 个关节角** | SDK 只提供 "零位 /home 配置"，**不代表手臂垂在体侧**；也无姿态库 | 手动使能后把臂摆到贴体重垂下，`get_joint_positions(["left_arm","right_arm"])` 记下来，存成 `POSE_DOWN` |
| 2 | **"指物" 的 14 个关节角**      | 同上；且 "指" 是整臂 + 末端朝向，角度取决于身高与目标高度          | 摆到 "肩前屈约 60°、肘近伸直、末端朝前"，记录并存成 `POSE_POINT`；再存一个 "安放 / 摆手" 角 `POSE_WAVE`           |
| 3 | **各关节限位（URDF）**         | 限位在机器人上的 `galbot_one_golf.urdf`，本机没有这份文件  | 真机 `cat` 该 URDF 或在 `set_config` 里读出 limit，抄进文档；**别凭感觉给 ±0.7 rad**                 |

同时待验（已知未确认项）：麦克风实际采样率、头部相机外参是否随转头自动更新（`get_transform` 现查现用就绕开了）、末端左右到底装了什么。

## 五、结论：编排里哪些是 "有依据"，哪些是 "待验假设"



| 编排内容                              | 状态                               |
| --------------------------------- | -------------------------------- |
| 转头看向目标、点头 / 侧头（2 DOF head）        | ✅ 有依据，接口现成                       |
| 原地转向对齐老人（set\_base\_pose rel (0)） | ✅ 有依据                            |
| 靠近 1.0–1.5 m 停住                   | ✅ 有依据（导航 + 到位阈值）                 |
| 降身与老人平视                           | ✅ 有依据（0.96–1.54 m；单次 3–4 s）      |
| 双臂下垂 / 收臂                         | ⚠️ 接口有，**角度待标定**                 |
| 整臂指物 + 夹爪闭合                       | ⚠️ 接口有（宽度可到 0），**角度待标定 + 末端待看机** |
| 摆手安抚                              | ⚠️ 可行，但摆动轴待实测                    |
| 跌倒 "深度贴地" 判据                      | ⚠️ 头无深度 → 改 2D 主判 + 立体复核         |
| 手势细节 "像不像人"                       | ❌ 无依据，属观感目标，只能真机看效果调             |

**一句话**：**凡是 "机器能不能做" 的问题，本表能回答；凡是 "做出来好不好看" 的问题，只能真机看。** 两者不许混着写。
