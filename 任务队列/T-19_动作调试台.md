# T-19 动作调试台（单模块演示 + 长链分段演示）

> 关联：T-17 数字孪生 / 《动作编排.md》全部模块
> 状态：**V1 已完成并实测** ｜ 2026-11-08

## 目标

1. **单模块演示**：单独界面（只有机器人），从模块库点选 M-01~M-15 / D 体态任意一个，立即执行该动作。
2. **长链分段演示**：四条链 × 分段，任选一段一次性完整演示该场景（自动复位 → 场景预置 → 动作序列）。
3. **与真机同一份命令**：动作定义单源 JSON，数字孪生与真机 SDK 调用一一对应；先电脑预处理跑通，再上真机。

## 交付

| 文件 | 说明 |
|---|---|
| `web/shared/motions.json` | **单源动作定义**：M-01~M-15 + D-1~D-4，每步 = SDK 原语序列 + 参数 + SDK 签名注释 |
| `web/shared/chains.json` | 四链 12 段（跌倒/认知/远程/守护），每段 = preset（场景预置）+ steps |
| `web/js/primitives.js` | 原语解释器：set_joint_positions（编组展开走单源 expandJoints）/ set_leg_height / set_base_pose / face_point / navigate_to_goal / move_rel / set_gripper_command / oscillate / stop_all / say / screen / elderly.* / cam.fly |
| `web/js/sdk-text.js` | **SDK 调用文本 + 编组展开规则的单源**（无依赖 ES module）：调试台日志、真机 dry-run、校验器三方共用；py 侧 `sdk_text()`/`expand_joints()` 为同逻辑镜像 |
| `server/verify_consistency.py` | **孪生↔真机一致性校验器**（四层：原语覆盖 / SDK 文本逐条 diff / 关节名 / URDF 限位），109 条命令全量校验，`python verify_consistency.py` 一键跑 |
| `web/lab.html` + `web/js/lab.js` | **动作调试台**：摄影棚舞台 + 模块库 + 详情卡 + SDK 调用日志 + 急停/复位 |
| `web/index.html` 主页面 | 左下「任务段演示」面板（选链 → 选段 → 整段演示） |
| `web/js/robot.js` | 新增 SDK 级原语：setLegHeight（剪叉升降）/ turnRel / moveRel / stopAll / setGripper（宽度↔关节角）/ 导航可中断 |
| `web/js/protocol.js` | `seq.run` 串行队列 + `seq.done` 完成回执（Python 同步等待） |
| `server/client.py` | `run_seq(steps)` 发送并阻塞等待孪生执行完毕 |
| `server/primitives.py` | 真机侧骨架：RealRobot stub（每个方法对应一个 SDK 原语，上真机时替换实现） |
| `server/run_motion.py` | `python run_motion.py M-13`（孪生）/ `--real`（dry-run 打印 SDK 调用） |
| `server/run_chain.py` | `python run_chain.py c1 2` / `c1 all` / `--real` |

## 关键标定（真机上线前需复核）

- **POSE_DOWN（双臂下垂）**：左右臂镜像安装——`left_arm_joint2=-90`、`right_arm_joint2=+90`。
  用 tcp 世界坐标数学扫描确认（j1=臂轴自转/薄片方向，j2=肩俯仰，j4=肘摆）。
- **POSE_POINT（指物）**：左夹爪臂 `left_arm_joint2=-35`（前伸偏下指低处目标）。
- **POSE_WAVE（摆手）**：右臂 `j2=-60, j4=-50` 起手，j2/j4 小幅振荡 2 回。
- **升降**：leg_joint1/2/3 = 0.94/2.58/2.33 × 行程比例 f，f = (z-0.96)/0.58。
- 上述全部是**目测近似**，真机标定后只改 `robot.js` 的 `POSES` 与 primitives 的 'down'。

## 踩坑记录

1. **编组键名坑**：groups 键是 `left_arm`（不是 `left`），判断分支写 `g==='left'` 永远为假，
   导致所有'收臂'动作实际把两臂都抬到 +90。用 `g.startsWith('left')` 修复。
2. **左右臂镜像安装**：肩俯仰 j2 正方向相反（left 负=垂 / right 正=垂），截图目测极易误判，
   必须用 tcp 世界坐标 y 值判定。
3. **浏览器模块缓存**：headless 复用 profile 时 ES module 缓存滞留旧代码，改代码后"看起来没生效"。
   bridge.py 加了 no-store 响应头 + 模块内 ROBOT_JS_VER/PRIM_JS_VER 版本标记排查。
4. **seq.run 并发**：preset 与 steps 分两条消息会并发执行 → protocol.js 加串行队列 + seq.done 回执。
5. **Windows 控制台 GBK**：动作名含 ↔ 等字符崩溃，primitives.py 顶部 stdout reconfigure utf-8。
6. **老人模型巨大化（穿模首因）**：elderly.js 归一化一次性测包围盒，glb 网格流式挂载未完成时
   包围盒极小 → 缩放爆炸成 3m+ 巨人。修复=robot.js 同款"连续 3 次稳定"轮询。
   且轮询用 await 后 _setup 必须改 async，否则整个模块解析失败、页面白屏。
7. **模型正面朝向**：Quaternius 木偶正反难辨，靠坐姿骨骼实测（hips 在原点 +Z 后方 0.299m）
   确认正面朝局部 +Z，yawOffset=0；落座锚点 SEAT.forward=0.30（臀部落到坐垫正中）。
8. **家具穿墙核算**：布局数组每项都要按"外形尺寸+yaw 旋转后的包围盒"核对墙内面，
   本轮修掉：床穿西墙、橱柜横穿东墙 1.26m 并与餐桌互穿、扶手杆贴墙过近。
9. **胸屏方向/位置（G1 正面朝 URDF -Y）**：屏幕长期"挂在肩关节"的根因是两处叠加：
   ①rotation(-π/2,0,π) 使法线背朝正面（与面朝方向 dot=-1）→ 正确旋转 (π/2,0,0)；
   ②躯干 glb 网格自带 x≈0.09 偏置，屏幕必须补偿 x=0.09 才在躯干正中；
   高度 modelH*0.65（URDF z，×scale1.49→世界 1.05≈锁骨下胸口）。
   修正方法论：别用截图目测，直接读 mesh 世界法线与面朝向量的 dot 值。
10. **镜像安装复核（TCP 数据链）**：j2=0 → 双臂 TCP y=1.04（与肩同高，水平 T-pose）；
    垂下 left=-90 / right=+90；举过头 left=+90 / right=-90。判断一律以
    gripper_base_link 世界 y 为准（垂下≈0.42），截图目测（正反面难辨）两次误导了标定。
11. **虚实一致性（回应用户"聊的动作链=真机动作"硬要求）**：仅"架构上同一份 JSON"不够，
    校验器首轮就抓到两处实锤不一致——
    ①py 侧 `groups:'down'` 未实现（真机会把字符串 'down' 发给 SDK）；
    ②`robot.*` 别名原语（chains.json 正式步骤在用）py 侧全部跳过；
    ③M-02 低头 head_joint2=-15° 超 URDF 限位 [-12.3,28.3]（真机被拒/截断，孪生却照演）。
    修复后以 `verify_consistency.py` 固化为回归门槛：改 JSON/原语后必须重跑。
    SDK 文本以 sdk-text.js 为单源，node 子进程与 py 实现逐字 diff。
12. **CSS2D 气泡隐藏必须用 object.visible**：CSS2DRenderer 每帧按 visible 重写
    element.style.display，`display='none'` 会被覆盖回显 → 气泡永不消失（收场两气泡重叠）。
    robot/elderly 气泡统一改 `visible` 控制。
13. **复位必须全关节归零**：reset() 只回 arms_home 时，M-11 降身的剪叉腿关节、
    M-15 的夹爪闭合角都会残留到下一次演示（机器人歪着站）。全 revolute 归零后再 arms_home。
14. **改完 .js 必须语法自检**：replace_in_file 撞上部分相似文本会产生重复签名等语法错误
    且整个 module 失效页面黑屏。快检法：`node -e "import('file:///…/x.js').catch(e=>console.log(e))"`。
15. **house.js 轴向约定**：yaw 使局部 +X 对准墙方向（东西墙 yaw=0），凡"沿墙长条"
    （墙板/踢脚线/玻璃/窗台/帘杆/门扇）必须建模 `box(L, h, T)`——长轴局部 X、厚度局部 Z；
    写成 `box(T,h,L)` 会整面墙横转 90° 甩出户型。窗帘等附属件法向偏移统一取
    "指向户型中心"的墙法线（挂屋内），验收用 eval 枚举世界坐标越界构件（修复后必须 0 处）。
16. **机器人朝向换算（实测校准，勿改符号）**：yaw=0 时正面朝世界 +Z（胸屏法线/头前向
    实测 (0,0,1)）→ 面朝向量 f(yaw)=(sin yaw, 0, cos yaw)，面向 (dx,dz) 的 yaw =
    atan2(dx, dz)。旧实现 atan2(-dx,-dz) 整体差 180°——moveRel 前进变倒退（用户观感
    "左右跑"）、navigate/face 到位背朝目标、face_point 反向。判朝向一律实测
    （screenObj 世界法线 / head_link1 局部 -Y 变换），改动前先跑 moveRel 位移三连测：
    yaw=0 时 +1 应到 (0,1)、-1 到 (0,-1)、navigate(2,0) 后 yaw=π/2。
17. **剪叉升降标定（run-time calibration）**：URDF leg_joint1..3 下限=0，剪叉只能向上
    伸——关节 0=全收最低、f≈0.8 峰值后过死点回落。归一化基准必须是"全伸姿态=1.6m 站立"，
    默认站姿=关节 0.8 量程（不是 0！），复位同。set_leg_height 的 z→f 必须经运行时实测
    曲线（_calibrateLeg 五点采样）反插值——剪叉"关节角→高度"强非线性，线性公式会让
    M-11"降低反升高"、且同参数孪生降幅≠真机（虚实出入）。
18. **NaN 关节污染（"手臂一旋转就没了"）**：update() 振荡处理 `center + amp*phase`
    撞上 center={关节:值} 对象 → 字符串 → NaN → setJointValue(NaN) 永久污染关节，
    变换链崩溃模型从场景消失，且 _applyPose 读 NaN 起点会让复位也救不回。三道防线
    已固化勿删：①center 按形态取值（数字/对象/缺省）；②setJointDeg 入口拒绝非有限值；
    ③_applyPose 起点 isFinite 过滤。NaN 类 bug 用 hook setJointDeg 抓调用栈定位最快。
19. **垂臂姿态要贴身（对称≠自然）**：j2 零位是 T-pose，j2=∓90 下转后手臂指向下但带
    27° 外张（TCP 相对肩侧偏 0.35m），呈八字不自然。必须加 j1=∓25 侧摆补偿
    （j1 是唯一侧摆关节，j3/j5 无侧向响应——扰动实测确认）→ 侧偏 0.05m。
    姿态标定看 TCP 相对肩的三维偏移，不能只验左右对称；预设改动必须同步
    sdk-text.js GROUP_PRESETS + primitives.py expand_joints + POSES.arms_home 三处。
20. **模型自带元素不要重复建模**：G1 躯干贴图（M_torso）上已画胸屏，自建屏幕 mesh 是
    重复悬挂。改用头顶 emote 气泡（CSS2D .bubble.emote，dataset.level 控 info/alarm 配色）
    呈现 screen.show。给模型"补挂"任何部件前，先 traverse 全 mesh 清单确认自带与否；
    CSS2D 新元素在 _load 里建时 cssRoot 用 constructor 存的 this._cssRoot（参数不可见）。
21. **左右镜像关节值禁止跨侧复制**：镜像安装（垂臂 left j2=-90 / right j2=+90，符号相反），
    左侧抬臂数值 j2=-60/j4=-50 直接给右臂会旋转 150° 举到头顶（TCP 三轴全反，M-13 实锤）。
    正确镜像 right=同值反号（+60/+50）。凡 left/right 共用一套数值必先反号，验收用
    "TCP 相对肩三轴比对"（镜像姿态应 y 等值、x 反号）。POSES/ motions.json / chains.json
    三处同步改，防 gesture 路径与 JSON 路径不一致。
22. **碰撞拦截层（非物理引擎）**：机器人移动是确定性动画，物理引擎会破坏动作时序；
    用 2D 拦截层——house.js buildColliders() 从 WALLS/FURNITURE_LIST 派生 AABB
    （墙按 door 开口切分、窗当实墙、家具 footprint 随 yaw 旋转取包围盒+膨胀 0.06），
    navigate/moveRel 帧内圆(0.28m)-AABB 检测+分轴滑动+终点回退可达点+起点脱困模式。
    实测注意：**footprint 的 yaw 旋转会把 w/d 互换**（sofa yaw=90 → x 方向窄 0.91），
    推算停位前先查 COLLIDERS 实际数据，别口算。改家具布局无需重建碰撞表（自动派生）。
23. **动态实体也要进碰撞 + 观感穿模≠物理穿模**：elderly.occupancy() 动态占位（站 0.4/
    倒地 0.9 保守圆，倒向随走路朝向变，圆比旋转 AABB 可靠）经 robot._dyn 注入 blocked。
    豁口条件是 door||pass（pass=无门垭口，漏了会把通道堵死、守护位被回退到半路）。
    布守护站位时避开倒地身体轴线（1.73m 长身体，正南站位+北向机位=透视完全重叠，
    观感"压人"）——站身体侧面面对面；交互镜头从角色面向侧拍（越肩）才有正脸。
24. **原语时长参数必须参与执行时序**：say/elderly.say 的 durationMs 曾只是气泡显示
    时长，执行器立即返回——单段跑视觉掩盖，连跑时"问完即答"节奏全乱（3s 秒完 vs
    应 35s）。真机 tts.play 阻塞至播完，孪生 execPrim 必须 await 同样时长。
    调试连跑/整链用 MutationObserver 挂 logList 收全量时间线（容器 60 条上限会
    挤掉早期记录，读日志方向=新在顶部 prepend，别取 slice(-3) 当最新）。
25. **运镜机位"双主角同框"数值验收**：每个 cam.fly 按"段结束时角色位置"做
    Frustum(50°/16:9)+包围球+目标 NDC(|x|<0.9) 检测——"target 朝 A"≠"B 在画内"
    （c4-s3 老人 NDC x=2.94 完全出画实锤）。两角色相距 d>3m 时机位距离下限=
    d/(2·tan36°)；新机位=target 取两角色中点、pos 沿垂直连线方向拉远。
    相机放室外时近墙淡化自动生效（updateWallFade），可放心用外部高机位。
