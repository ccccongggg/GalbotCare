# 证据收集规范（开发期间随手执行）

> 目的：评分项"测试与改进 10 分"与答辩问答全靠证据。证据必须在**尝试发生的当下**采集，事后无法补拍。
> 原则：**每次真机尝试，前后各留一段；改一次参数，复测一轮。**

## 1. 命名规范（存入 `交付包/06_素材库/`）

```
06_素材库/
├── screenshots/  命名：YYYYMMDD_HHMM_<功能>_<内容>.png     例：1108_1015_FR01_告警手机端.png
├── videos/       命名：YYYYMMDD_HHMM_<功能>_<前后>.mp4     例：1107_1540_FR05_改进前.mp4
└── logs/         命名：YYYYMMDD_HHMM_<功能>.jsonl/csv      例：1107_1540_FR05_runlog.csv
```

- 视频片段 10 秒级即可；"改进前/后"必须**同机位、同场景、同指标**才构成有效对比。
- 截图必须包含时间戳或日志窗口（评委要能对上"运行记录"）。

## 2. 采集时机清单

| 时机 | 必须采集 | 谁负责 |
|---|---|---|
| 每次上真机前 | 预告一句话进 `runlog.csv`（改了什么、预期看什么） | 操作者 |
| 每次失败 | 手机录屏机器人现场表现（10s+）+ 复制终端报错 | 陪跑记录人 |
| 每次修复后复测 | 同机位复测视频 + 通过/失败次数记入 runlog | 操作者 |
| 每次参数改动 | 参数前后值写进 ITER 表对应格 | 操作者 |
| 跌倒演示成功 | 手机端告警卡片截图（带时间）+ 本地语音时间对照 | D |
| 回忆录生成 | 网页端时间轴截图 | D |
| 远程点选导航 | 手机操作 + 机器人运动同框视频（一人拍手机一人拍机器人） | D + B |

## 3. 日志最低字段（NFR-09）

每条事件：`ts, task_id, skill, event, params, result, latency_ms`。
- 跌倒告警额外记：判定帧数、置信度、触发时延。
- 导航额外记：目标距离、到位耗时、是否超时。
- 人工接管额外记：`takeover` 事件 + 原因（对应接管记录表）。

## 4. 复查红线

- [ ] 截图/录屏中**不得出现 API Key、内网 IP（可打码）**
- [ ] 录屏中不得出现与演示无关的个人隐私信息
- [ ] 所有 ITER 数字能回溯到对应素材文件（文件名对得上）
